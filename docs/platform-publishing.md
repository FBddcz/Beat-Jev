# 多平台发布方案

## 先发布网页链接

当前项目最适合先作为 H5/PWA 发布。把仓库连接到 Render、Railway、Fly.io 或自有 VPS，运行 `npm start`，即可得到一个 HTTPS 地址。手机浏览器打开即可玩，也可以“添加到主屏幕”。

当前版本需要 Node 服务处理会话、commitment 和 Jev API，请不要只上传 `public/` 到 GitHub Pages。`ALLOWED_HOSTS` 要填写部署后的域名；Jev Key 仍只保存在服务端会话内存中。

## 平台能力对照

| 平台 | 当前 HTML 能否直接上传 | 推荐方式 | 适合的第一步 |
| --- | --- | --- | --- |
| 手机浏览器 / H5 | 可以 | Render、Railway、VPS | 先上线网页链接 |
| 微信小游戏 | 不可以直接上传 DOM 页面 | 用 Cocos Creator 或 Canvas 重做渲染层，复用 `game.mjs` 规则 | 做微信版本 |
| 抖音小游戏 | 不可以直接上传 DOM 页面 | 用 Cocos Creator 或 Canvas 适配小游戏 API | 做抖音版本 |
| 快手 / QQ / 支付宝小游戏 | 通常不能直接上传 DOM 页面 | 按各平台 Canvas/小游戏 SDK 适配 | 有流量需求再做 |
| 小红书 | 可分享 H5；小游戏入口以平台审核能力为准 | 先发 H5，再评估小程序/小游戏适配 | 先用笔记或私信分享链接 |
| iOS / Android 应用 | 可以包装 | PWA、Capacitor 或原生 WebView | 需要应用商店分发时再做 |

## 微信 / 抖音小游戏需要做什么

1. 注册对应开放平台账号，创建小游戏项目并完成主体、隐私和类目审核。
2. 保留现有规则层：回合、角色、分数、commitment、Jev 请求协议可以继续复用。
3. 重做一层 Canvas 渲染和触控输入，把当前 HTML/CSS 组件替换为场景画布、左右触控区和结算动画。
4. 把 Jev 请求放到自己的 HTTPS 服务端，小游戏只请求自己的后端；不要把 API Key 放进小游戏包。
5. 配置合法域名、隐私协议、客服和版本信息，使用平台开发者工具真机测试后提交审核。

## 推荐发布顺序

**第一阶段：H5 链接。** 一套代码同时覆盖 iPhone、安卓、微信内置浏览器和普通浏览器，最容易验证玩法传播性。

**第二阶段：微信小游戏。** 如果 H5 有稳定留存，再把规则层迁移到 Cocos，先做微信版本；Cocos 的渲染层也方便后续适配抖音和快手。

**第三阶段：抖音 / 快手 / App。** 根据真实流量来源决定是否投入平台专用适配，不需要一开始维护多套代码。

## 审核前检查

- 游戏说明写清楚“仅娱乐，不涉及真实金钱或投资建议”。
- API Key、会话 Cookie 和模型请求只在服务端处理。
- 音效默认开启，但页面提供关闭开关；保留 `prefers-reduced-motion` 支持。
- 所有外链、字体和资源使用 HTTPS 或随包发布。
- 提供隐私说明、用户反馈入口和版本号。
